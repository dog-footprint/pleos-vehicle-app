동작 원리

입력 두 갈래(개 프로필, 차량 신호)가 순수 함수 규칙을 거쳐 화면·음성·차량 제어·기록으로 나갑니다. 규칙의 모든 상수는 docs/CARE_RULES.md의 출처 표에 묶여 있습니다.

입력

  • 프로필 견종 · 크기 · 털 · 단두종 · 생년월 · 체형 · 호흡기/심장 · 멀미 · 몸무게 · 자리 · 고정 방식
  • 탑승 시 마지막 식사 시간
  • 차량 자리별 실내 온도 · 공조 설정/풍량/전원 · 좌석 점유/벨트 · 창문 · 문/트렁크 · 브레이크 · 기어 · 주행거리 · 배터리
  • 내비 목적지 남은 거리/시간 · 휴게소 안내
→

규칙 (care/ComfortRules.kt)

  • 생애 단계 (AAHA, 크기별 노령 기준)
  • 적정 온도 범위 18–24 °C에서 특성별 보정, 10–29.5 °C 절대 한계
  • 열사병 경보 (단두종·호흡기 24 °C, 그 외 27 °C)
  • 휴식 간격 120/90분, 멀미·더위 단축, 하한 45분
  • 식후 2시간 경고, 4시간 참고
  • 급제동 묶음 감지, 이동/정차 판정, 편안함 지수
→

출력

  • 화면 상태별 홈 4종, 온도 정수 + 판정 한 단어, 고정 경고 슬롯(위험·주의·정보)
  • 음성 Pleos TTS 17문장 (끄면 알림음)
  • 차량 제어 자동 조절 (실험 플래그): 공조 온도·풍량·방향
  • 진정 모드 음악 / 이야기
  • 발자국 여행별 거리·시간·휴식·이벤트·지수·기분

06

주차 · 펫 단독

홈의 세 번째 상태. 운전자가 내리고 개만 남은 순간을 잡습니다.

데모 영상에뮬레이터 검증

탑승 중 정차 상태에서 운전석 문이 열렸다 닫히면 "펫 단독" 상태로 바뀌어 혼자 남은 시간, 자리 온도, 공조 전원을 크게 보여 주고 "코코 혼자 있어요. 공조가 꺼져 있어요 / 실내 n도예요"를 음성으로 알립니다. 차량이 꺼지면 앱도 꺼지므로 원격 감시가 아니라 "내리기 직전·직후의 확인"이라는 한계를 화면에 그대로 둡니다. 근거: 외기 21 °C에서 10분 만에 실내 32 °C (McLaren 2005), 창문을 조금 열어도 효과 없음.

발자국

여행마다 쌓이는 기록. 사진 없이 차량 데이터만으로 만듭니다.

데모 영상에뮬레이터 검증

다른 사람이 직접 조작해 보려면

Pleos Connect는 전용 에뮬레이터가 있어 실차 없이도 모든 기능을 만질 수 있습니다. 지금 당장 되는 길부터 순서대로.

1. Pleos Connect 에뮬레이터 + APK 지금 가능

우리가 개발·검증한 방식 그대로. 상대방 PC에 한 번만 설치하면 됩니다. 검증한 환경은 Apple Silicon Mac(arm64 이미지)입니다.

  1. Android Studio 설치 → SDK Manager → SDK Update Sites에 Pleos 애드온 사이트(crp-arm64-sys-img.xml, Pleos 문서의 에뮬레이터 설정 페이지) 추가 → 시스템 이미지 Pleos Connect v2.1.0 (API 34) 설치
  2. Device Manager → Automotive → 새 AVD, 이 이미지 선택, RAM 4 GB, cold boot. 이름을 Pleos_Connect로 두면 저장소 스크립트가 그대로 맞습니다
  3. APK 설치: adb install -r apk/dog-footprint_dog-footprint_release.apk (APK는 저장소에 포함, 약 58 MB). Pleos Playground 자격 증명이 빌드에 들어 있어 음성·내비 연결에 추가 설정이 없습니다
  4. 런처에서 dog-footprint 실행 → 위치 권한 허용 → 프로필 만들기 → 홈에서 탑승
  5. 차량 신호 넣기 (둘 중 하나):
    · 가상 콘솔: adb forward tcp:8088 tcp:8088 후 브라우저에서 http://127.0.0.1:8088 — 기어, 주행거리, 브레이크, 공조, 창문, 문, 좌석을 클릭으로 조작
    · 스크립트: scripts/vehicle-sim.sh forward 다음 gear Drive · odometer +0.5 · window rl 60 · brake 100 · hvac …
  6. 콘솔 없이도: 설정 → 개발자 버튼(급제동 · 휴식 도달 · 온도 27/16 °C · 운전자 하차)로 핵심 상황을 바로 재현
# 저장소를 받은 경우 — 데모 프로필(코코)까지 한 번에
git clone git@github.com:dog-footprint/pleos-vehicle-app.git && cd pleos-vehicle-app
emulator -avd Pleos_Connect &
adb install -r apk/dog-footprint_dog-footprint_release.apk
scripts/vehicle-sim.sh forward        # 가상 콘솔 포트 연결
scripts/vehicle-sim.sh gear Drive && scripts/vehicle-sim.sh odometer +0.3
데모 프로필 주입(scripts/demo-seed.sh)은 디버그 빌드 전용입니다. 릴리스 APK를 쓰는 사람은 프로필을 직접 만들면 됩니다(견종 하나 고르면 30초).

알려진 한계

  • 동승자가 남는 경우 — 운전자만 내리고 동승자가 차에 남아도, 앱은 운전석 문이 닫힌 뒤 30초가 지나면 "코코 혼자 있어요"로 판단할 수 있습니다. 조수석 점유 신호(Seat.occupancy ROW_1_RIGHT)가 켜져 있으면 펫 단독으로 넘어가지 않도록 했지만, 뒷좌석 동승자나 점유 센서가 없는 차에서는 구분하지 못합니다. 에뮬레이터는 좌석 점유 값을 반전해 보고하므로(CLAUDE.md) 실차에서 다시 확인해야 합니다.
  • 시동 상태 — Vehicle SDK에 시동/전원 상태 읽기 API가 없어(IgnitionState 상수만 존재) "내리기 전 확인"은 P 전환과 운전석 문 열림을 기준으로 띄웁니다. 전원 차단 경고등(Safety.registerPowerDownWarningIndicator)이 오면 1단계 알림을 앞당깁니다.
  • 공조 유지 — 시동을 끈 뒤 공조를 유지하는 API(유틸리티 모드 등)가 없어 "공조 켜기"는 시동을 켜 둔 동안만 유효합니다. 릴리스 빌드(Vehicle Control 미승인)에서는 버튼 대신 "공조를 켜 두고, 유틸리티 모드로 내리세요" 안내만 보입니다.

2. 저장소 공유

GitHub 조직 dog-footprint의 비공개 저장소 pleos-vehicle-app. 공모전 규정상 심사용 계정을 collaborator로 초대해야 하고, 팀 외부 체험자도 같은 방식으로 초대하면 됩니다. 저장소에는 APK, 데모 영상, 이 문서, 근거 문서(docs/CARE_RULES.md), 에뮬레이터 스크립트가 모두 있습니다. 직접 빌드하려면 JDK 21과 .env(Playground Client ID/Secret)가 필요하므로, 빌드 없이 APK만 쓰는 쪽이 간단합니다.

3. 실차 · 테스터 배포 심사 필요

Pleos Connect 차량에 올리려면 Playground에서 App Market 심사를 거쳐야 합니다(앱 심사 가이드). 그 전에 CONTROL_CAR_* 권한을 빼야 하고, TTS·FusedLocation·Vehicle Control은 우리 프로젝트에서 아직 "Not Available Yet"이라 승인 범위에 따라 기능이 안내 전용으로 줄어듭니다. Playground에 별도 테스터 배포 기능이 있는지는 확인하지 못했습니다 — 2차 전에 Playground 콘솔에서 확인할 항목입니다.

4. 현장 시연 (2차 라이브 PT, 전시)

  1. 에뮬레이터가 켜진 노트북 한 대, 외부 모니터에 미러링. 앱은 디버그 빌드 + scripts/demo-seed.sh로 코코 프로필을 미리 넣어 둠
  2. 심사위원이 직접 누를 수 있는 것: 탑승(식사 팝업), 자동 조절, 진정 사운드, 휴식 완료, 여행 종료, 설정의 개발자 버튼
  3. 진행자가 옆에서 신호를 넣는 것: vehicle-sim.sh window rl 60, brake, gear — 터미널 한 줄씩
  4. 소리가 중요한 장면(음성 안내, 음악)은 에뮬레이터 오디오를 스피커로 출력
  5. 보험: 데모 영상(3:11)을 같은 화면에 띄울 수 있게 준비

5. 에뮬레이터 없이 (웹 체험판) 미구현

심사위원이나 일반 관람객이 브라우저에서 만져 보게 하려면 규칙(ComfortRules)을 JS로 옮기고 홈 화면을 흉내 낸 웹 시뮬레이터가 필요합니다. 차량 신호 대신 슬라이더(온도·창문·기어)를 두면 "견종을 바꾸면 적정 범위가 어떻게 달라지는가"를 가장 빨리 보여 줄 수 있습니다. 이 저장소에는 아직 없고, 만든다면 반나절 분량입니다.
